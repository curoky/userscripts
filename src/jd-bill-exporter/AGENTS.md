# JD Bill Exporter

## Purpose

在京东 PC 新版订单列表增加 CSV 导出面板。用户在京东原生页面选择要导出的年度并回到第一页，脚本只遍历当前筛选的全部分页。每个下单年度生成 `jd-orders-YYYY.csv`，完成后显示下载链接。若用户选择京东提供的旧年份合集，则按实际下单年份分文件；没有订单的旧年份不生成空文件。

安装 `dist/jd-bill-exporter.user.js` 到 Violentmonkey，打开 `https://order.jd.com/center/list.action` 或 `https://order.jd.hk/center/list.action`。在京东页面选择“今年内订单”或具体年份、“全部”订单状态，清空搜索并回到第一页，等待订单加载完后点击右下角“导出当前年度 CSV”。导出期间保持页面打开，不手动切换筛选、翻页或修改订单。

年份选择、筛选条件和返回第一页由用户负责。脚本不得增加自己的年份菜单、自动切换京东年份、自动遍历所有年份或自动返回第一页。“近3个月订单”不是全年，遇到此筛选应提示用户选择年度；当前不是第一页时应提示用户返回，不导出残缺年度。

本脚本导出订单列表展示金额，**不是实际支付流水或退款后的净支出**。保留已取消、零元及赠品订单，保留页面状态和支付方式。退款、价保、优惠组成、运费及多种支付工具的实付拆分不在当前页面的可靠字段范围内。CSV 中的“汇总订单金额（非净支出）”仅在独立订单和拆单父订单行填值，子单行留空；只对该列求和，不能同时累计父单与子单的“订单金额”列。

## Module boundaries

- `main.ts`、`style.css.txt`：导出按钮、进度、取消及下载链接。样式是文本资产，构建时内嵌到 JS，无需 CSS 插件或外部文件。页面数据用 textContent 写入，订单只存在当前页面内存中。
- `order-page.ts`：京东 DOM 解析、输入校验、分页和当前已选年度识别。
- `exporter.ts`：读取用户选好的年度，从第一页开始只点击“下一页”；等待订单请求完成与 DOM 稳定后读取下一页。
- `orders.ts`：以整数分保存金额，保留明确父子关系和跨页上下文，验证重复订单内容。
- `csv.ts`：按下单年度生成 UTF-8 BOM、CRLF 和带引号的 CSV，金额校验与汇总去重。
- `userscript.config.ts`：metadata 与单文件构建配置的唯一来源。CSS 必须打包进 user.js，不能留下独立安装依赖。

不得直接调用京东内部接口或读取登录凭据、签名、框架内部状态。仅监听 Resource Timing 中 `pcorder_center_list` 的请求完成信号，不读取请求体或响应。无需 GM 权限、持久化、外部依赖或新增网络请求。

## Observed JD integration (2026-10-31)

已通过 Chrome 调试连接核对 `order.jd.hk` 的 PC 新版订单页（pc_orderList 0.0.41）。

0.2.0 构建产物已在用户手动选好的 2025 年订单页实测：保持筛选不变，读完 3 页、53 个订单和 9 组拆单，CSV 下载后校验通过。有 3 组父子金额不一致，原始金额保留并正确标记。CSV 共 62 行数据（14 个独立订单、9 个父单、39 个子单）、16 列。在第 3 页再次导出会提示用户返回第一页，不自动导航，也不生成残缺文件。

初版还核对过 2026 年 5 页、85 个订单和 14 组拆单，包含零元子单，所有父子金额一致。`order.jd.com` 使用同一布局的适配尚未实测；旧年份合集按年分文件、取消、未完成响应及空年度用虚构数据测试。
- 列表为 `[class*='listContent-']`，每个订单卡片为 `[class*='orderCard-']`。选择器匹配 CSS module 名称前缀，避免依赖哈希。
- `[class*='splitBanner-']` 提供明确的父订单号、时间、总额和拆单原因。实际页面的原因是“由于商品存储的库房不同，故拆分为以下订单分开配送”。
- 父单标题只在第一个子单前出现，多个子单属于列表中的相邻独立节点，**不是标题父容器内的全部后代**。按文档顺序读取父单标题及订单卡片，跨页保留最近的父单上下文。只有带 `splitOrderHeader-` 标记且下单时间及币种匹配的子单才关联该父单；遇到普通卡片清空上下文。不得仅凭相同时间、商家或订单号前缀推断拆单。
- 真实页面有 141.90 元父单，子单金额分别为 141.90、0.00；另有三子单及六子单合计与父单总额相同的组。零元子单不能删除。
- “今年内订单”是全年筛选，“近3个月订单”不是年度筛选。年度菜单还可能提供 `YYYY前订单`，此合集需要按实际年份拆分。
- 只适配新版卡片布局；旧表格布局、无法识别的币种、缺失金额或不明确拆单关系应停止并说明，不输出假装完整的年度 CSV。

父子合计不一致保留原始金额并在 CSV 和下载链接标记；不强行分摊差额。父子订单号以单引号前缀保存为文本，避免 Excel 的 15 位精度截断；商品等文本防止 CSV 公式注入。商品明细一单一行，包含名称、数量、可识别的 SKU，不猜测商品成交单价。

每页请求最多等待 30 秒，不无限重试。总页数、年度、状态或重复订单内容发生变化时停止。当前筛选全部分页完成前不生成下载链接；中断后由用户返回第一页重试。刷新页面清空内存中的 CSV。

## Release checklist

1. 行为变化时更新 metadata 的 SemVer。
2. 运行 `pnpm format`、`pnpm check`，确认 JS 内嵌样式且 dist 没有独立 CSS 文件。
3. 用真实京东页面手动选择年份，检查完整分页、父子金额校验及 CSV 下载。测试夹具使用虚构数据，不提交真实订单、地址、账号或导出的账单。
4. 同步源码、测试、文档及构建产物，不新增 README。
